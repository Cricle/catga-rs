# Persistent Flow Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the first pure-Rust Catga Flow release: persistent state, optimistic CAS storage, abandoned-flow claiming, and a compensating local flow API.

**Architecture:** Create a focused `catga-flow` crate so flow state and execution do not expand `catga-core`. `catga-memory` implements the shared `FlowStore` contract with `DashMap` entries and per-record CAS state. The local `Flow` builder holds ordered closures and compensates completed steps in reverse order; persistent execution uses store versions and owner heartbeats rather than process locks.

**Tech Stack:** Rust 2024, Tokio, async-trait, DashMap, Arc, atomics, root `catga-tests` integration package.

- [ ] **Step 3: Define store operations and memory semantics**

```rust
#[async_trait]
pub trait FlowStore: Send + Sync {
    async fn create(&self, state: FlowState) -> CatgaResult<bool>;
    async fn update(&self, expected_version: i64, next: FlowState) -> CatgaResult<bool>;
    async fn get(&self, id: &str) -> CatgaResult<Option<FlowState>>;
    async fn try_claim(&self, flow_type: &str, owner: &str, stale_after: Duration) -> CatgaResult<Option<FlowState>>;
    async fn heartbeat(&self, id: &str, owner: &str, version: i64) -> CatgaResult<bool>;
}
```

Store each state in an `ArcSwap<FlowState>` slot indexed by `DashMap`; CAS compares the immutable state pointer and never holds a map guard during a retry loop. Claim candidates must be running, type-matched, and stale; each candidate is claimed through that slot's CAS.
